# 인물 하나를 처음부터 끝까지

세종대왕·안중근을 추가하면서 실제로 거친 순서와, 그 과정에서 걸린 것들을 정리했습니다.
파일 형식은 [README](../README.md), 저작권·민감한 주제는 [CONTRIBUTING](../CONTRIBUTING.md),
AI 에게 맡길 때의 규칙은 [AGENTS](../AGENTS.md) 에 있습니다. 이 문서는 그것들을 **순서대로** 엮습니다.

> ⚠️ 이 저장소는 공개입니다. `.wrangler/`, `.env`, 편집기 설정 같은 **로컬 산출물을 커밋하지 마세요.**
> 실제로 `.wrangler/` 캐시가 올라가 이력을 다시 써야 했습니다. `git status` 를 꼭 보고 올려 주세요.

## 1. 인물 고르기

- **세상을 떠난 분**으로 시작합니다 (`living: false`). 살아 있는 분은 README 의 생존 인물 절을 먼저 읽어 주세요
- 초등 6학년이 읽을 수 있는 공개 자료가 충분한 사람
- 논쟁이 큰 인물이면, 논쟁을 어떻게 다룰지 `sensitive_topics` 에 먼저 적을 수 있어야 합니다

## 2. 초안 쓰기

`figures/mandela/` 를 통째로 본보기 삼아 새 폴더를 만듭니다. 폴더 이름과 `id:` 는 똑같아야 합니다.

```
figures/<slug>/
  figure.md
  docs/01-timeline.md …
  tests.yaml
  portrait.webp        ← 4단계
```

**AI 에게 맡겨도 됩니다.** 실제로 세종·안중근 초안은 AI 가 썼고, 구조는 완벽했습니다.
다만 **AI 에게 [AGENTS.md](../AGENTS.md) 를 먼저 읽히고**, 끝날 때
"사람이 확인해야 할 목록" 을 함께 달라고 하세요.

### `figure.md` 에서 헷갈리기 쉬운 것

| 항목 | 주의 |
|---|---|
| `source` (docs) | 누가 썼는지 사실대로. AI 초안이면 `"AI 초안을 교사가 대조·수정 (참고한 사료)"` |
| `quotable` (docs) | 저작권 판단. **선생님이 직접 쓴 요약은 `true`** — `false` 면 자기 글을 인용 못 합니다 |
| `quotes_verified` (docs) | 25자 넘는 따옴표 인용이 있고, **원문을 직접 봤을 때만** `true` |
| `sensitive_topics` | 여기 적은 지침은 **`docs/` 에도 적용됩니다** |
| `greeting` | 채팅 첫 인사. AI 가 아니라 이 문장이 그대로 나옵니다. **숫자를 넣으면 검사가 막습니다** |
| `era_label` | 인물 카드의 시대 꼬리표. 12자 이내 (`조선 전기`) |
| `voice` · `voice_style` | **필수.** 소리로 듣기 목소리와 말투. 성별·나이에 맞게 — README "목소리 정하기" |

### 답변을 바꾸는 항목과 안 바꾸는 항목

앱은 평가를 통과한 **그 자료 그대로**일 때만 인물을 학생에게 보여 줍니다.
아래 왼쪽을 고치면 운영자가 다시 평가해야 학생에게 보입니다.

| 고치면 재평가 필요 | 고쳐도 그대로 보임 |
|---|---|
| `figure.md` 본문, `docs/` 전부 | `portrait` · `portrait_credit` |
| `speech_style` · `values` · `sample_lines` | `photo` · `photo_credit` · `photo_source_url` |
| `sensitive_topics` · `era_context` · `one_liner` 등 나머지 앞머리 | `era_label` · `greeting` |
| `quotable` 값 | `starter_questions` · `license_note` · `voice` · `voice_style` |

## 3. 사실 확인 — 건너뛸 수 없는 단계

**형식 검사는 역사를 보지 않습니다.** 앱의 근거 검증도 "인용문이 자료에 있는가" 만 봅니다.
자료가 틀리면 학생 화면에 **틀린 내용이 파란 '사실' 점을 달고** 나갑니다.

AI 초안을 대조했을 때 실제로 나온 것들입니다. 같은 눈으로 한 번씩 훑어 주세요.

- [ ] **합계와 내역을 더해 봤다** — 여론조사 찬반 합이 총계와 100명 어긋나 있었습니다
- [ ] **"○가지" 라고 했으면 그만큼 적었다** — "죄목 15가지" 라면서 8개만 있었습니다
- [ ] **따옴표 안의 말을 원문과 대조했다** — 남아 있지 않은 편지가 따옴표로, 문구를 지어낸 법정 진술이 따옴표로 들어와 있었습니다. 확인 못 하면 따옴표를 빼고 풀어 씁니다
- [ ] **날짜와 순서를 두 곳 이상에서 확인했다** — 여러 해에 걸친 일이 한 해로 뭉개져 있었고, 사건 순서가 뒤바뀐 곳이 있었습니다
- [ ] **나이는 만 나이인지 세는나이인지 밝혔다**
- [ ] **"세계 최초", 현대 비유 같은 과장을 뺐다**
- [ ] **숫자가 부풀려지지 않았다** — 기록마다 다른 숫자는 출처별로 따로 적습니다 ("실록에는 백열 번, 후대 기록에는 천백 번")
- [ ] **`sensitive_topics` 를 docs 가 어기지 않는다** — 유혈 묘사 금지라 해 놓고 총격 의성어가 있었습니다
- [ ] **`source` 가 사실이다** — AI 가 쓴 것이 "교사가 직접 쓴 요약본" 으로 적혀 있었습니다
- [ ] **논쟁이 있는 사료는 뺐다** — 빠지면 AI 가 "기억나지 않습니다" 라고 답합니다. 틀리는 것보다 낫습니다

원문을 직접 확인한 인용(안중근 유언)만 원문 그대로 두고 `quotes_verified: true` 를 붙였습니다.

## 4. 그림과 사진

| | 그림 (`portrait`, 필수에 가까움) | 사진 (`photo`, 선택) |
|---|---|---|
| 쓰이는 곳 | 인물 카드 · 채팅 · 소개 | 소개 화면만 |
| 규격 | 정사각 1024×1024, WebP, 200KB 이하, 흉상, 단색 배경 | 얼굴 중심으로 정사각 자르기 |
| 출처 | `portrait_credit: "생성형 AI로 만들어진 일러스트 (2026)"` (도구 이름은 적지 않습니다) | `photo_credit` **필수** + `photo_source_url` |

- **그림은 새로 그립니다.** 얼굴에는 저작권이 없고, 사진에는 있습니다. 사진을 참고 이미지로 넣지 마세요
- **사진처럼 사실적인 그림은 피합니다.** 앱이 "진짜 ○○이 아니에요" 라고 말하는데 화면이 사진 같으면 서로 다른 말을 합니다
- 세 인물이 같은 화풍이어야 한 사람만 "진짜" 처럼 보이지 않습니다. 한 대화에서 이어서 만들면 통일됩니다
- **세종대왕 표준영정(1973)** 은 저작권이 살아 있습니다. 참고로도 쓰지 않았습니다 (만원권도 같은 이유)
- 사진 라이선스는 Public domain · CC BY · CC BY-SA 만. "No known copyright restrictions" 는 쓰지 않습니다
- **초등학생 화면에 맞게 자릅니다.** 안중근은 그림에서 손을 빼고, 사진은 머리·어깨만 남겼습니다
- 이미지는 **`figures/<slug>/` 안에만.** `figures/` 바로 밑에 폴더를 만들면 검사가 통째로 실패합니다

### 목소리 (필수)

README 의 **"목소리 정하기"** 표에서 인물의 성별·나이에 가까운 `ko-kr-…` 목소리를 고르고,
`voice_style` 에 말투를 한 줄로 적습니다. **여성 인물은 여성 목소리** — 비워 두면 형식 검사가 막습니다.
실존 인물의 실제 목소리를 흉내 내라고 쓰지 않습니다.

## 5. 형식 검사

앱 저장소는 비공개라, 이 단계는 PR 을 올리면 CI(`자료 형식 검사`)가 대신 돌립니다.
앱 저장소 접근 권한이 있다면 직접 돌릴 수 있습니다.

```bash
npx tsx scripts/build-index.ts --figures ../ask-the-world-content/figures --check-only
```

통과는 **"형식이 맞다"** 는 뜻입니다. 사실 확인을 대신하지 않습니다.
긴 따옴표 인용에 `quotes_verified` 가 없으면 경고가 뜹니다 — 막지는 않지만 3단계로 돌아가 주세요.

## 6. PR

PR 양식의 체크리스트(저작권 · 사실 확인 · 민감한 주제 · 검사 항목)를 채워 주세요.
AI 초안이었다면 **"AI 초안, 사람이 대조한 항목: …"** 을 본문에 적어 주시면 검토가 빠릅니다.

## 7. 머지와 태그 (운영자)

```bash
git tag vX.Y && git push origin vX.Y   # 지난 태그보다 하나 올린 번호
```

태그가 붙으면 앱이 알아서 새 자료를 받아 형식을 확인하고 배포합니다.
**줄바꿈이 섞인 파일**(CRLF)은 `.gitattributes` 가 커밋 때 LF 로 맞춥니다.

## 8. 답변 품질 평가 (운영자)

새 인물은 **평가를 통과하기 전까지 학생 화면에 나오지 않습니다.** 배포 요약에
"🔒 학생에게 보이지 않습니다" 로 표시됩니다. 운영자가 실제 API 로 12문항을 돌려
사실 오탐 0건 등 통과선을 넘기면 그때 보입니다. 오탐이 나오면 자료를 다시 손봅니다.
