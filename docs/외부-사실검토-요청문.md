# 외부 AI 사실 검토 요청문

새 인물 자료를 학생에게 열기 전에 Gemini·GPT 같은 **다른 AI 에게 사실 검토를 맡길 때** 쓰는 요청문입니다.
Claude 서브에이전트로 세 명을 검토했더니 합계 약 46만 토큰이 들었습니다(2026-11-02). 그래서 판정은 외부 AI 가 하고,
증빙 확인은 기계가 합니다.

1. 아래 요청문을 붙여 넣고, 그 인물의 `figure.md`, `docs/*.md` 4개, `tests.yaml` 을 첨부합니다
2. 돌려받은 JSON 을 `D:\dev\eval-review\<slug>-factcheck.json` 처럼 **영문 경로**에 저장합니다
   전체 인물을 한꺼번에 맡길 때는 "한 번에 5명씩, 결과 파일이 이미 있는 인물은 건너뛰기"로 나눠 시킵니다
   (결과는 인물마다 `{figure, checked_sentences, summary, findings}` 객체 — 아래 배열 형식도 스크립트가 받습니다)
3. `python -I scripts/check-quotes.py <그 파일 또는 D:\dev\eval-review 폴더>` — 구절이 실제 페이지에 있는지만 봅니다
   - `MISS`·`증빙없음` 은 받아들이지 않습니다
   - `브라우저`(브리태니커 등 자동 요청을 막는 곳)는 브라우저로 열어 확인합니다
4. 확인된 지적만 **한 번에 모아** 고칩니다(AGENTS.md 19번). 고친 뒤 형식 검사 → 평가

```text
당신은 초등학교 6학년 "역사 인물 인터뷰" 수업용 자료의 사실 검토자입니다.
첨부한 파일은 한 인물의 자료입니다: figure.md(인물 설정), docs/*.md(근거 문서 4개), tests.yaml(평가 문항).
AI 가 이 자료를 근거로 인물처럼 답하므로, 틀린 문장은 학생에게 그대로 사실로 전달됩니다.

[할 일]
docs 의 모든 문장과 figure.md 의 사실 주장(one_liner, era_context, greeting, starter_questions, values,
sample_lines, sensitive_topics, "## 어떤 사람이었나" 절), tests.yaml 질문의 전제를 하나씩 확인하세요.
웹에서 신뢰할 출처를 직접 열어 대조하세요. 우선순위: 각 문서의 source_url → 국가·학술 기관 백과사전
(한국민족문화대백과사전, Britannica 등) → 1차 사료·기관 아카이브. 위키백과는 보조로만 쓰세요.

[무엇을 잡아야 하나]
A. 사실 오류: 날짜·숫자·이름·장소·순서가 출처와 다름. 특히 "다른 시점의 숫자를 섞은 것"
   (예: 1837년 발표는 12종인데 1845년 책의 13종을 1837년 일로 씀), 간행 연도와 저술 연도 혼동.
B. 출처에 없음: 그럴듯하지만 어느 출처에도 없는 세부(인원 명단, 기관 설치, "끝까지", "틈틈이" 등).
C. 규칙 위반 — 역사적으로 맞더라도 잡으세요:
   1) figure.md 는 docs 에 있는 사실만 말해야 합니다. docs 에 없는 내용이 figure.md 에 있으면 지적.
   2) 최상급·평가("대표하는", "황당무계한", "가장")를 사실처럼 씀.
   3) 인과·동기·속마음을 지어 붙임("~하기 위해", "~때문에", "서둘러", "백성을 생각하며").
   4) 범위를 넓힘("모든", "끝없이", "평생", "늘", "~만").
   5) 출처의 유보("~로 보인다", "아마", "~라고 여겨진다")를 지우고 단정함.
   6) 통설·전설을 사실로 씀(유레카 순간, 같은 날 사망 등).
D. 출처 주소: source_url 이 실제로 그 내용을 담은 페이지인지(없는 절이라 대표 페이지로 넘어가지 않는지).

[증빙 규칙 — 가장 중요]
- 지적마다 url 과 quote 를 붙이세요. quote 는 그 페이지 본문에 **글자 그대로** 있는 15~60자 구간입니다.
  원문 언어 그대로 쓰고, 번역·요약·말 바꾸기는 하지 마세요. 저희가 프로그램으로 그 구절이 페이지에 있는지 확인합니다.
- 구절을 직접 열어 보고 옮길 수 없으면 verdict 를 "확인불가"로 하고 quote 는 비워 두세요. 주소를 추측해 만들지 마세요.
- 문제없는 문장은 나열하지 말고, 맨 끝 요약에 "확인한 문장 수"만 적으세요.
- 출처끼리 말이 다르면 "틀림"이 아니라 verdict 를 "출처마다다름"으로 하고, fix 는 유보를 붙인 문장으로 주세요.
- 붙인 quote 가 오히려 원래 문장을 뒷받침하면(예: "형이 둘" → "셋째 아들") 지적하지 마세요.

[하지 말 것]
파일을 고쳤다고 하거나 새 파일을 만들지 마세요. 출처 없이 새 사실을 추가하자고 하지 마세요.
고치는 문장은 "출처가 말하는 만큼"으로 줄이는 쪽이 기본입니다.

[출력 형식]
아래 JSON 배열을 코드 블록 하나로 주고, 그 아래에 한국어로 3~5줄 요약을 붙이세요.
[
  {
    "file": "docs/02-....md 또는 figure.md 또는 tests.yaml",
    "sentence": "문제 문장 원문 그대로",
    "verdict": "틀림 | 출처에없음 | 출처마다다름 | 규칙위반 | 확인불가",
    "rule": "A~D 중 해당 기호와 한 줄 설명",
    "url": "증빙 페이지 주소",
    "quote": "그 페이지 본문에 글자 그대로 있는 구절",
    "fix": "고친 문장(한국어, 한 문장에 사실 하나, 연도 명시) 또는 \"삭제\""
  }
]
```
